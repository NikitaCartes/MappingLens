# MappingLens — Описание сервиса

*(English version: [SERVICE.md](SERVICE.md))*

MappingLens — **stateless read-only** сервис для поиска, перевода, сравнения и инспекции
маппингов Minecraft (Yarn / Mojmap / Intermediary / Obfuscated). Состоит из трёх артефактов:

- **`index`** — offline-индексатор; единственный писатель SQLite-индекса.
- **`serve`** — stateless HTTP-сервер (Ktor/Netty), открывает индекс только на чтение.
- **`frontend/`** — браузерный explorer маппингов (React + Vite), потребляет REST API.

Сервер ничего не декомпилирует и не мутирует: исходники/байткод читаются по требованию из
read-only GitCraft-стора, индекс открывается с `PRAGMA query_only=ON`.

## Доступные фичи

| Фича                   | Описание                                                                                                                                                            |
|------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Поиск по маппингам     | FTS5-поиск классов/методов/полей в одной версии; каждая строка результата — имя во всех неймспейсах сразу                                                           |
| Перевод имён           | Перевод имени класса/метода/поля между неймспейсами (`from`→`to`), с авто-определением типа                                                                         |
| Diff символов          | Added / removed / renamed классов, методов и полей между двумя версиями + сводка                                                                                    |
| Diff исходников        | Список изменённых файлов и unified/git-патч исходников между версиями (фильтр по пути/функции)                                                                      |
| История по версиям     | Один класс/член сразу по всем версиям: диапазоны версий с одинаковым ответом, слежение за переименованием через intermediary; несколько ключей за запрос            |
| Хэш тела метода        | Тело метода, хэшированное по каждой версии диапазона, соседи с общим хэшем слипаются: ответ на «есть ли что перепроверять» там, где diff исходников показывает косметику декомпилятора |
| Compare Yarn↔Mojmap    | Таблица соответствия членов одного класса между Yarn и Mojmap                                                                                                       |
| Байткод                | Дизассемблированный байткод класса (ASM Textifier) в любом неймспейсе, text или JSON                                                                                |
| Исходники              | Декомпилированный `.java` класса из artifact-store (namespace yarn/mojmap)                                                                                          |
| Иерархия наследования  | Супертипы + подтипы класса (ASM-скан named-jar'а), для right-click «View Inheritance» в UI                                                                          |
| Find All References    | Обратный индекс использований класса/метода/поля (on-demand ASM-скан named-jar'а, кэш per version/namespace)                                                        |
| Проверка существования | Батч-проверка, что классы/члены живы в версии (`POST /exists`, ASM-скан named-jar'а) — валидация таргетов миксинов при апдейте мода                                 |
| Матрица целей миксина  | Набор целей миксина по каждой версии диапазона (`POST /validate`), соседи с общим ответом слипаются. Ловит уехавший из тела вызов, которого не видит проверка сигнатуры |
| Токены исходника       | Резолв каждого идентификатора `.java` в owner/name/descriptor (JavaParser symbol-solver) → `{source, tokens}`; питает member-level right-click (Copy AW/AT/Mixin)   |
| Версии                 | Список проиндексированных версий с флагами доступности неймспейсов и counts, порядок — semver (новые сверху)                                                        |
| OpenAPI / Swagger      | Машиночитаемая спецификация (`/openapi.json`, `/openapi.yaml`) + Swagger UI (`/docs`)                                                                               |
| Frontend explorer      | Браузерный UI: выбор версии, фильтры неймспейса/типа, debounced-поиск, кросс-неймспейс карточки с click-to-copy                                                     |
| Blame по версиям       | Колонка «в какой версии последний раз менялась строка» в просмотрщике исходников: один `git blame` по репозиторию исходников за запрос (`/blame/{version}/{class}`) |

## Требования

- **JDK 21** (Gradle toolchain `languageVersion 21`, `jvmTarget JVM_21`). Стек: Kotlin 2.2.20, Ktor 3.2.3, Exposed 0.56, sqlite-jdbc.
- **Node.js** (для frontend).
- **Данные на диске:**
  - Для `index` — источники: `artifact-store` (с подпапками `mappings/`, `mc-versions/`, `decompiled/<ver>/`, `remapped-mc/<ver>/`), `yarn`, `mojmap`, `intermediary`.
  - Для `serve` — **готовый индекс** по пути `database.path` (иначе сервер падает на старте с подсказкой запустить `index`). Источники репозиториев на старте не нужны, но `diff`/`bytecode`/`source` лениво читают jar'ы из `artifact-store` во время запроса.
  - Для `/openapi.*` и `/docs` — ресурс `openapi/mappinglens-api.yaml` на classpath (поставляется в jar).

> **Совместимость схемы.** Индекс, собранный до переписывания, не содержит колонок `versions.sort_index` / `classes.presence`, и `serve` на нём вернёт 500 `no such column: versions.sort_index` — лечится пересборкой через `index`.
>
> Имена ищутся во втором файле, `mappinglens-search.db`, рядом с `database.path`. Без него `serve` не стартует, а индекс, собранный раньше, несёт только старую общую таблицу `search_index` внутри основного файла. Обычный запуск **`index`** чинит и то и другое: он строит таблицу поиска для каждой версии, у которой её нет, читая имена из самого индекса (52.3 млн строк за 485 с на 526 версий, маппинги не переиндексируются), и удаляет старую таблицу. После этого `VACUUM` над основным файлом возвращает её 14.9 ГБ файловой системе.
>
> Индекс, собранный до появления колонок со счётчиками, не содержит `versions.class_count` / `method_count` / `field_count`, и `serve` на нём вернёт 500 `no such column: versions.class_count`. Колонки добавляет сборка через `index`, а на готовом индексе — `dev/migrate-version-counts.sql` (добавляет и заполняет, пересборка не нужна). Строка версии с пустыми колонками отвечает верно, через прежний путь с группированным подсчётом.

## Конфигурация

HOCON-файл `application.conf` (создаётся из встроенного шаблона при первом запуске, если отсутствует).
Все пути переопределяются переменными окружения.

| Ключ                                                     | По умолчанию          | Env / CLI                               | Назначение                                                                                |
|----------------------------------------------------------|-----------------------|-----------------------------------------|-------------------------------------------------------------------------------------------|
| `ktor.deployment.host`                                   | `0.0.0.0`             | `HOST`, `-host`                         | Адрес привязки                                                                            |
| `ktor.deployment.port`                                   | `8080`                | `PORT`, `-port`                         | Порт                                                                                      |
| `mappinglens.database.path`                              | `data/mappinglens.db` | `MAPPINGLENS_DB_PATH`                   | SQLite-индекс (serve — RO, index — пишет)                                                 |
| `mappinglens.sources.artifact-store`                     | `data/artifact-store` | `MAPPINGLENS_ARTIFACT_STORE`            | Корень стора (mappings/mc-versions/decompiled/remapped-mc)                                |
| `mappinglens.sources.yarn-repo`                          | `data/yarn`           | `MAPPINGLENS_YARN_REPO`                 | Источник Yarn (только индексация)                                                         |
| `mappinglens.sources.mojmap-repo`                        | `data/mojmap`         | `MAPPINGLENS_MOJMAP_REPO`               | Источник Mojmap (только индексация)                                                       |
| `mappinglens.sources.intermediary-mappings`              | `data/intermediary`   | `MAPPINGLENS_INTERMEDIARY`              | Источник Intermediary (только индексация)                                                 |
| `mappinglens.sources.unobfuscated-intermediary-mappings` | `""` (выкл.)          | `MAPPINGLENS_UNOBFUSCATED_INTERMEDIARY` | Источник Intermediary для unobfuscated-релизов, отдельный репозиторий (только индексация) |
| `mappinglens.search.max-results`                         | `200`                 | —                                       | Верхняя граница `limit` для поиска                                                        |
| `mappinglens.search.default-results`                     | `50`                  | —                                       | `limit` по умолчанию                                                                      |
| `mappinglens.indexing.initial-versions`                  | `[]` (все)            | —                                       | Версии, которые собирает команда `index`; **игнорируется `serve`**                        |
| `mappinglens.indexing.mappings`                          | `"yarn,mojmap"`       | `MAPPINGS`                              | Какие именованные маппинги читает команда `index`: `yarn`, `mojmap` или оба               |
| `mappinglens.indexing.only-releases`                     | `false`               | `ONLY_RELEASES`                         | Индексировать только стабильные релизы; см. примечание под таблицей                       |

`indexing.only-releases` оставляет версии, которым Mojang даёт тип release. Всё, что Mojang
типизирует как snapshot, уходит вместе со снапшотами: pre-релизы, release candidate, первоапрельские
версии и combat-снапшоты. Варианты `_unobfuscated` уходят с ними же, потому что каждый дублирует
сборку, которая индексируется под собственным id. `indexing.mappings` исключает именованный маппинг
из чтения маппингов, из сканирования исходников и из reference-индекса, и `/versions` после этого
отдаёт это пространство имён как отсутствующее у всех версий.

**Плагины Ktor:** ContentNegotiation (kotlinx JSON, `prettyPrint`, `encodeDefaults`, `ignoreUnknownKeys`),
CallLogging, CORS (`anyHost`, методы GET и POST, заголовок `Content-Type`), RateLimit (200 запросов / 60 с — только
на группы `/api/v1`), StatusPages (`IllegalArgumentException`→`400 invalid_query`, прочее→`500 internal_error`),
и плагин кэш-заголовков, выставляющий `Cache-Control` на успешных `/api/v1`-ответах (см. правила контракта ниже).

## Запуск

```sh
# 1. Собрать read-only индекс (единственный писатель БД)
./gradlew run --args="index"

# 1a. Пересобрать только указанные версии (например, после того как GitCraft перестроил
#     версию на новом билде yarn). `-versions` перекрывает `indexing.initial-versions`;
#     уже проиндексированная версия пересобирается только вместе с `-force`.
./gradlew run --args="index -force -versions=1.21.4,26.2"

# 2. Запустить сервер (stateless, RO). serve — команда по умолчанию,
#    если первый аргумент отсутствует или начинается с '-'.
./gradlew run --args="serve"            # слушает :8080

# 3. Frontend (dev): Vite проксирует /api -> http://localhost:8080
cd frontend
npm install
npm run dev                              # http://localhost:5173
npm run build                            # статика в dist/ (tsc + vite)
```

`main()` берёт `args[0]` как подкоманду только если она не начинается с `-`; известные команды —
`index` (пишет БД) и `serve` (RO). Любой другой токен печатает usage и выходит с кодом 2.

Прод-вариант frontend: задеплоить `dist/` как статику и проксировать `/api` на работающий `serve`
(в compose это делает контейнер `frontend`, см. ниже).

## Docker

Compose-файл поднимает два сервиса: `mappinglens` держит `serve` запущенным и сам достраивает
данные (GitCraft пополняет артефакт-стор и репозитории исходников, `index` обновляет индекс),
`frontend` отдаёт собранный бандл.

```sh
docker compose -f docker/docker-compose.yml up -d --build
```

| Сервис        | Порт на хосте                         | Dockerfile                   |
|---------------|---------------------------------------|------------------------------|
| `mappinglens` | `8080` → API и Swagger UI на `/docs`  | `docker/Dockerfile`          |
| `frontend`    | `3000` → UI                           | `docker/Dockerfile.frontend` |

Контекст сборки у обоих образов — корень проекта. `.dockerignore` исключает `frontend/node_modules`
и `frontend/dist`, сами исходники frontend остаются в контексте. Сборка frontend — `npm ci` и
`npm run build` на Node 24, дальше `dist/` отдаётся nginx. Бандл ходит в API по своему же origin
(`/api/v1/…`), поэтому `docker/nginx.conf` проксирует `/api/` на `http://mappinglens:8080`; наружу
порт `8080` открыт только для прямых запросов к API.

В образе API: fat jar MappingLens (собирается отдельным слоем на JDK 21), GitCraft (требует JDK 25),
чекауты `FabricMC/intermediary`, `RelativityMC/intermediary`, `FabricMC/yarn`, `RelativityMC/yarn`
и пресеты GitCraft. `VOLUME` в Dockerfile нет, тома объявлены в compose-файле.

| Каталог в томе `/data`       | Что лежит                                                                |
|------------------------------|--------------------------------------------------------------------------|
| `artifact-store/`            | Артефакт-стор GitCraft (`mappings/`, `mc-versions/`, `decompiled/`, ...) |
| `repos/yarn`, `repos/mojmap` | Git-репозитории декомпилированных исходников                             |
| `index/mappinglens.db`       | SQLite-индекс                                                            |
| `state/`                     | Маркеры цикла обновления, в том числе снимок стора `store.files`         |
| `gradle/`                    | Gradle home для прогонов GitCraft                                        |

Цикл `docker/entrypoint.sh`, интервал `UPDATE_INTERVAL_SECONDS`:

1. Обновляет четыре чекаута и считает один отпечаток по их refs (`git ls-remote`).
2. В манифесте Mojang новая версия → первый пресет из `MAPPINGS`, то есть `mojmap`, если mojmap не
   отключён. Прогон не ограничен новой версией: GitCraft собирает всё, чего нет в сторе, этим же
   заполняется и пустой стор. Mojmap не нужны ни intermediary, ни yarn, поэтому версия попадает в
   поиск в этом же цикле. При `ONLY_RELEASES` прогон идёт с `--only-stable`, а из манифеста
   сравнивается только id релиза, поэтому новый снапшот цикл не запускает.
3. Опубликованный билд yarn выше того, что лежит в артефакт-сторе, либо на диске его вообще нет →
   пресет `yarn`, при необходимости с `--refresh-only-version`. Если в `MAPPINGS` нет yarn, шаг
   пропускается.
4. Индексация. Шаги 2 и 3 только собирают, индексирует один этот шаг, и смотрит он на стор, а не на
   код возврата сборки. Листинг `artifact-store/mappings` сравнивается со снимком `state/store.files`
   от последней успешной индексации: сначала `index -force -versions=<...>` по версиям, у которых
   файлы изменились, затем обычный `index` по версиям, которых в базе ещё нет. Снимок пишется только
   после успеха, поэтому рестарт контейнера между сборкой и индексацией ничего не теряет, а
   удалённый `index/` собирается заново целиком.
5. Индекс изменился → рестарт `serve`: сервер мемоизирует счётчики версий и пути к jar'ам.

Сравниваются все версии, а не только свежие. Если набор несобираемых версий не изменился и ни один
mapping-репозиторий не двигался, прогон GitCraft пропускается: версия ждёт публикации intermediary
или yarn.

Пресеты `docker/presets/mojmap.args` и `docker/presets/yarn.args` — по одному аргументу в строке,
строки с `#` игнорируются; передаются GitCraft как `--preset=<файл>`.

| Переменная                | По умолчанию        | Назначение                                                                   |
|---------------------------|---------------------|------------------------------------------------------------------------------|
| `UPDATE_INTERVAL_SECONDS` | `3600`              | Пауза между проверками                                                       |
| `MAPPINGS`                | `mojmap yarn`       | Какие маппинги собирать и индексировать; индексатор читает ту же переменную  |
| `ONLY_RELEASES`           | `false`             | Собирать и индексировать только стабильные релизы (GitCraft `--only-stable`) |
| `REFS`                    | `all`               | Охват reverse-reference индекса: `all`, `releases` или `none`                |
| `PORT`                    | `8080`              | Порт `serve`                                                                 |
| `MAPPINGLENS_*`           | пути внутри `/data` | Те же переменные, что и вне контейнера                                       |
| `GITCRAFT_JAVA_OPTS`      | —                   | Опции JVM для прогона GitCraft, например `-Xmx16g`                           |
| `INDEX_JAVA_OPTS`         | —                   | Опции JVM для `index`, например `-Xmx4g`                                     |
| `SERVE_JAVA_OPTS`         | —                   | Опции JVM для `serve`, например `-Xmx4g`                                     |

Build-args `GITCRAFT_REPO` и `GITCRAFT_REF` указывают, откуда брать GitCraft. Нужны опции
`--preset`, `--artifact-store-path`, `--override-repo-target` и `--fabric-intermediary-repo`.

> На пустом томе первый прогон строит все версии с нуля и занимает дни, `serve` поднимется
> только после появления индекса. Готовый артефакт-стор монтируется поверх `/data/artifact-store`
> (пример закомментирован в compose-файле).

## Эндпоинты

Базовый префикс — `/api/v1`. Все эндпоинты — `GET`, если не указано иное. `{className...}` / `{name...}` — catch-all:
остаток пути (со слэшами) склеивается в internal-имя класса.

### Мета (без rate-limit)

| Эндпоинт            | Описание                                                                           |
|---------------------|------------------------------------------------------------------------------------|
| `GET /`             | Текстовый указатель на `/docs` и `/openapi.json`                                   |
| `GET /health`       | Liveness, отвечает `ok`                                                            |
| `GET /openapi.json` | OpenAPI 3.1 как **настоящий JSON** (YAML парсится SnakeYAML и реэкспортируется)    |
| `GET /openapi.yaml` | OpenAPI 3.1 в YAML                                                                 |
| `GET /docs`         | Swagger UI (включён по умолчанию, `includeDocs=true`)                              |

### Версии

| Эндпоинт                         | Описание                                                                                         |
|----------------------------------|--------------------------------------------------------------------------------------------------|
| `GET /api/v1/versions`           | Список всех версий (флаги `hasYarn/Mojmap/Intermediary` + counts), порядок semver (новые сверху) |
| `GET /api/v1/versions/{version}` | Метаданные одной версии (`404 version_not_found`, если нет)                                      |

**Вариант** — повторная индексация билда, который уже есть в списке под собственным id: GitCraft
делает `<id>_unobfuscated` из предеобфусцированного джарника Mojang. Поле `variantOf` называет
исходный билд и равно `null` у самостоятельной версии. Варианты не попадают в листинг, в перебор
`/history` и в выбор версии по умолчанию: один билд, показанный дважды, читается как две версии и
ставит лишнюю ступеньку между каждой парой соседей. Вернуть их можно параметром
`includeVariants=true` в `/versions`, `/history` и `/references`. По имени вариант отвечает всегда,
включая `/versions/{id}`.

### Поиск

| Эндпоинт             | Описание                                                                          |
|----------------------|-----------------------------------------------------------------------------------|
| `GET /api/v1/search` | FTS-поиск классов/методов/полей в версии; каждая строка — имя во всех неймспейсах |

Параметры: `q` (обяз.), `version` (по умолч. последний release), `type` (`class/method/field/all`),
`namespace` (`yarn/mojmap/intermediary/all`), `limit` (1–200, по умолч. 50), `offset` (≥0), `exact` (`true/false`),
`includeSynthetic` (`true/false`, по умолч. `false`).
`q` поддерживает форму `Owner#member` / `Owner.member` / `Owner/member`.

Строка-член несёт дескриптор трижды: `intermediaryDescriptor` — как его хранит индекс, плюс
`yarnDescriptor` и `mojmapDescriptor` — официальный дескриптор, переписанный через классы этой
версии. Именно именованные два сверяет `/exists`, поэтому ключ, собранный из строки поиска,
уходит туда без перевода. Оба заполняются одним запросом на всю страницу результатов. Неймспейс,
имени в котором у строки нет, дескриптора тоже не получает, а тип, которого версия не называет,
остаётся как есть — так же, как класс из JDK. `/diff` по-прежнему отдаёт только intermediary.

`score` лежит в диапазоне от `0` до почти `1`, и **больше значит лучше**. Строки приходят сразу в
порядке от лучшей к худшей, то есть порядок выдачи и поле согласованы. Значение выводится из ранга
bm25 конкретного запроса и сравнивает результаты только внутри одного вызова.

`includeSynthetic` (по умолчанию `false`) решает, отдавать ли тела лямбд. В маппингах
`lambda$addRecipes$0` назван так же, как любой другой метод, поэтому поиск `addRecipes` раньше
возвращал лямбду рядом с методом, внутри которого она написана. У оставленной строки стоит
`synthetic: true`. FTS-таблица contentless, фильтровать в ней нечего, поэтому отсев идёт после
матча, а запрос берёт вчетверо больше страницы, чтобы страница осталась полной.

### Перевод

| Эндпоинт                               | Описание                                                                              |
|----------------------------------------|---------------------------------------------------------------------------------------|
| `GET /api/v1/translate`                | Перевод имени между неймспейсами (`name`, `from`, `to`, `version?`, `type=auto`)      |
| `GET /api/v1/translate/class/{name...}` | Шорткат перевода класса (тип фиксирован `class`; `from/to` по умолч. `yarn`→`mojmap`) |
| `POST /api/v1/translate/{version}`      | Батч-перевод ключей; тело `{from, to, keys[]}`; ответ `{results:[{key, translated, type, intermediary}]}` |

Батч-форма принимает те же ключи, что `/exists` — internal-имя класса либо
`owner:name:descriptor` — записанные в `from`, до 2000 за запрос. `translated` — целый ключ в `to`
вместе с дескриптором, поэтому результат отправляется в `/exists/{version}` как есть. Ради этого
эндпоинт и сделан: `/search` и `/diff` отдают intermediary-дескрипторы, `/exists` сверяет
именованные, и без батча разрыв закрывается руками по одному типу.

Дескрипторы переводятся потипно через таблицу классов: дескриптор состоит из имён классов и
примитивов, а таблица знает каждый класс версии во всех неймспейсах. Опорой служит official-вариант.
Тип, которого версия не знает (класс JDK), остаётся как есть. Ключ без дескриптора разрешается
только при единственном совпадении имени: у перегруженного имени `translated` будет `null`, а не
догадка.

### Diff

| Эндпоинт                 | Описание                                                                                                  |
|--------------------------|-----------------------------------------------------------------------------------------------------------|
| `GET /api/v1/diff`       | Символьный diff (added/removed/renamed классов/методов/полей) + summary                                   |
| `GET /api/v1/diff/files` | Список изменённых файлов (`format=json`) или raw-патч (`format=patch/git`)                                |
| `GET /api/v1/diff/patch` | Unified/git-патч исходников (фильтры `path`/`file`/`function`, `context`, `limit`) или JSON с метаданными |

Параметры diff: `from`, `to` (обяз.); `namespace` (для `/diff` — `yarn/mojmap/intermediary`, для
`/diff/files` и `/diff/patch` — только `yarn/mojmap`); `type`, `package`, `class`, `changeType`, `limit`.

- `package` — префикс пакета над всем diff'ом, читается в `namespace`:
  `net/minecraft/world/level/block` для mojmap, `net/minecraft/block` для yarn.
  `class` — ровно один класс по внутреннему имени в
  `namespace` (перечисляет добавленные/удалённые/переименованные члены по имени с `owner`/`descriptor`;
  `summary` совпадает с `/diff/files` для того же класса). `class` приоритетнее `package`.
- `/diff/files?format=patch` и `/diff/patch` принимают `ignoreWhitespace` (по умолч. `false`):
  схлопывает ханки, отличающиеся только пробелами/переносами/переотступами. Патчи минимальны по
  построению (Myers O(ND)) — класс с парой правок даёт пару ханков, а не переписанный целиком файл;
  прежний LCS-путь остаётся лишь фолбэком для почти полностью переформатированных файлов.

### История по версиям

| Эндпоинт                      | Описание                                                                                |
|-------------------------------|-----------------------------------------------------------------------------------------|
| `GET /api/v1/history?q=<key>` | Один класс/член по всем версиям сразу: список диапазонов (`spans`) с одинаковым ответом |

Параметры: `q` (обяз., повторяемый — до 50 ключей за запрос), `namespace` (`yarn/mojmap/intermediary`,
по умолч. `mojmap`), `from`/`to` (ограничивают перебор версий; порядок границ не важен, неизвестная
версия → `404`), `releasesOnly` (по умолч. `false` — перебирать только релизы), `includeVariants`
(по умолч. `false`, см. «Версии»). Граница может называть версию, которую перебор потом пропустит,
поэтому ограничивать снапшотом или вариантом можно. Ключ `q` — internal-имя класса (точки допустимы) или `owner:name`; третий сегмент
`:descriptor` принимается ради совместимости с ключами `/references` и `/exists`, но в отборе не
участвует.

Ответ — `{namespace, results[]}`, по одной записи на каждый `q`, в порядке запроса, поле `query`
повторяет исходную строку дословно. `type` = `class`/`method`/`field`/`unknown`. Каждый `span` —
диапазон подряд идущих версий с одинаковым ответом: `from` (старшая), `to` (младшая), `versions`
(сколько версий), `present`. Для класса заполнены `intermediary`/`yarn`/`mojmap`, для члена —
`owner` (в запрошенном неймспейсе) и `members[]` (по записи на перегрузку).

- Класс отслеживается не по имени, а по intermediary-имени самого нового совпадения, поэтому
  переименование и переезд в другой пакет остаются одной историей: имя из любой версии даёт один и
  тот же ответ.
- Из того же отслеживания следует, что два написания одного члена дают одинаковые спаны и разные
  значения `query`. Имя, которым член зовёт конкретная версия, лежит в `members[]` её спана, а не
  в `query`. И `ResourceKey:location`, и `ResourceKey:identifier` отвечают всей историей: один спан
  читается как `"mojmap": "location"`, следующий как `"mojmap": "identifier"`.
- Unobfuscated-релизы (всё после 1.21.11) своих маппингов не содержат. Если индексатору задан
  `sources.unobfuscated-intermediary-mappings`, intermediary у них есть, и история работает как на
  любой другой версии. Проверить состояние индекса можно по `hasIntermediary` в `/api/v1/versions`.
- Без этого источника имя, взятое из такой версии, само по себе отвечало бы только за неё, поэтому
  класс дополнительно ищется в ближайшей предыдущей версии с intermediary — по простому имени,
  которое переезд пакета сохраняет. Найденное intermediary-имя и восстанавливает остальную историю.
- Два имени, живущие в одной версии, — это два класса, и связаны они не будут: у класса одно имя на
  версию. Так `util/filefix/virtualfilesystem/Node` не приклеивается к `world/level/pathfinder/Node`,
  хотя простое имя у них общее. Цена правила — без отдельного источника класс, переименованный
  (а не переехавший) уже после 1.21.11, историю до 1.21.11 не получит.
- Именованные дескрипторы в индексе не хранятся, поэтому смена сигнатуры видна по
  `members[].intermediaryDescriptor`.
- `present: false` с непустым `owner` — класс жив, а **сам класс члена с таким именем не
  объявляет**; `owner: null` — исчез класс.
- `present: false` с `reason: "inherited"` — член объявлен в супертипе, и вызов по-прежнему
  разрешается; `declaredIn` называет этот супертип в запрошенном неймспейсе, а `members[]`
  описывает его объявление. Без `reason` члена действительно нет — ни у класса, ни выше. Супертип
  читается из named-джара самой новой версии диапазона, у которой есть и класс, и джар, по одному
  заголовку класса за раз, а дальше отслеживается через индекс как любой другой класс, поэтому
  переименование супертипа внутри диапазона на ответ не влияет. У 13 снапшотов 2018-2019 годов
  `sort_index` пуст, из-за чего они встают в конец общего порядка, поэтому опорная версия берётся
  из запрошенного диапазона, а не из порядка по всему индексу.
- `type: "unknown"` теперь тоже несёт span'ы: значит, такого члена в индексе нет нигде, а span'ы
  говорят, на каких версиях. Раньше здесь возвращался пустой список, и это читалось как ошибка в
  запросе.
- `/history` смотрит в индекс маппингов, `/exists` — в джарник, под который собран мод. При
  расхождении прав джарник.
- Версии-двойники (`1.21.11` и `1.21.11_unobfuscated`) идут в порядке версий подряд, а yarn- и
  intermediary-имена у двойника пустые, поэтому такая пара раньше всегда давала два соседних
  span'а. Теперь перебор пропускает варианты; вернуть прежнее поведение можно через
  `includeVariants=true`, а убрать заодно и снапшоты — через `releasesOnly=true`.

### Хэш тела метода

| Эндпоинт                       | Описание                                                                            |
|--------------------------------|-------------------------------------------------------------------------------------|
| `GET /api/v1/bodyhash?q=<key>` | Тело метода, хэшированное по каждой версии диапазона, соседи с общим хэшем слипаются |

Параметры: `q` (обяз., повторяемый, до 50: `owner:name` или `owner:name:descriptor`), `namespace`
(`yarn`/`mojmap`, по умолч. `mojmap`), `from` и `to` (оба обязательны), `releasesOnly`,
`includeVariants`, `normalize` (`named` по умолчанию либо `intermediary`). Диапазон ограничен 60
версиями, счёт идёт после фильтров, потому что каждая версия стоит открытия джара и чтения одной
записи.

Это ответ на вопрос «менялось ли поведение между A и B», которого не даёт `/diff/patch`: тот
работает по декомпилированному исходнику и показывает косметику декомпилятора как изменение даже
с `ignoreWhitespace=true`. Ответ — `{namespace, normalize, results[]}`, запись `{query, spans[]}`,
span `{from, to, versions, hash}`. `hash` пуст там, где метода в версии нет, поэтому дырка видна
как дырка. Без дескриптора все перегрузки имени хэшируются вместе, отсортированные, чтобы ответ не
зависел от порядка объявления.

Хэш покрывает инструкции, метки переходов, таблицу try/catch и размеры фрейма. ASM раскрывает
константный пул при чтении, а `SKIP_DEBUG` убирает номера строк и имена локальных переменных,
поэтому одна пересборка хэш не двигает. `normalize=intermediary` сначала переименовывает типы
классов через intermediary — это и позволяет хэшу пережить переименование класса или переезд
пакета; имена членов в обоих режимах остаются как их пишет неймспейс, поэтому переименованный
вызов виден. На `LivingEntity.baseTick` по 16 релизам от 1.21 до 26.2 граница ложится на 1.21.9,
где `WorldBorder.getDamageSafeZone` стал `getSafeZone`, а `WorldBorder.getCenterX` держит один
хэш на всех 16.

Два потолка. Тело лямбды — отдельный метод, и в него обход не заходит, поэтому изменение внутри
лямбды хэш объемлющего метода не двигает; индекс `$12` в `lambda$baseTick$12` нормализуется,
поэтому лишняя лямбда, добавленная выше, его тоже не двигает. И у unobfuscated-версии нет
intermediary-имён, поэтому при `normalize=intermediary` её классы остаются под своими именами —
границу обфускации span не переживает ни в одном режиме.

### Матрица целей миксина

| Эндпоинт                | Описание                                                     |
|-------------------------|--------------------------------------------------------------|
| `POST /api/v1/validate` | Набор целей миксина, проверенный по каждой версии диапазона   |

Параметры строки запроса: `from` и `to` (оба обязательны), `releasesOnly`, `includeVariants`.
Диапазон ограничен 60 версиями, счёт идёт после фильтров. Тело —
`{namespace, targets: [{id, owner, method, descriptor?, at?}]}`, до 50 целей, где `at` — это
`{value, target}`, `value` равно `INVOKE` или `FIELD`, а `target` — полный
`owner:name:descriptor`. Без `descriptor` берутся все перегрузки имени, без `at` проверяется одна
сигнатура.

Ответ — `{namespace, results[]}`, запись `{id, spans[]}`, span
`{from, to, versions, status, atCount, closest, movedTo}`. Пять статусов:

- `ok`: метод на месте, и если задан `at`, то и инструкция на месте. `atCount` говорит, сколько
  раз, — это те номера, которые `@At(ordinal = N)` считает от 0 до `atCount-1`.
- `renamed`: имя есть, дескриптор другой, нужный лежит в `closest`.
- `inherited`: член объявлен в супертипе. Вызов разрешается, но миксин применяется к классу, где
  метод объявлен, поэтому цель должна называть супертип — его и даёт `closest`.
- `call_moved`: метод на месте, инструкции из `at` в теле нет. `movedTo` называет метод, где вызов
  теперь лежит.
- `missing`: ни метода, ни близкого объявления. `movedTo` всё равно заполняется, если ровно один
  другой метод класса держит этот вызов, — так выглядит переименованный метод.

`call_moved` — то, ради чего эндпоинт и сделан. Уехавший из тела вызов не трогает ни одну
сигнатуру, поэтому `/exists` молчит, а точка инъекции ломается тихо. `ServerPlayer#adjustSpawnLocation`
живёт с 1.21 по 26.2 без изменений, а с 1.21.9 его вызов границы сидит в
`PlayerSpawnFinder#findSpawn`. Переезд внутри класса виден прямо из того же разбора класса, переезд
наружу сопоставляется через `/diff/references` с ближайшей более старой версией, где вызов ещё был.

Пара «версия-цель» стоит чтения одной записи джара, поэтому две цели из самой постановки по 16
релизам от 1.21 до 26.2 отвечают за 72 мс. Супертипы читаются по одному заголовку класса и только
на промахе.

Два потолка. Вызов, уехавший в лямбду того же метода, читается как `call_moved`, и `movedTo`
называет `lambda$stopSleeping$9` буквально, потому что именно это цель для миксина, а индекс
лямбды гуляет по версиям. И значение `@At`, которое не называет одну инструкцию (`HEAD`, `RETURN`,
`CONSTANT`), отклоняется, а не угадывается.

### Compare

| Эндпоинт                                       | Описание                                                         |
|------------------------------------------------|------------------------------------------------------------------|
| `GET /api/v1/compare/{version}/{className...}` | Таблица соответствия членов (методы+поля) Yarn↔Mojmap для класса |

Параметры: `from` (по умолч. `yarn` — выбирает колонку поиска класса и проверку доступности),
`to` (по умолч. `mojmap`, см. замечание ниже).

Ответ: obf-ключённая таблица членов, выравнивающая класс по обоим неймспейсам, включая члены,
присутствующие только с одной стороны. Исходники не читаются. Поле `status` на уровне члена:
`matched`, `yarnOnly`, `mojmapOnly`, `unmappedYarn`, `synthetic`, `initializer` или `unmapped`
(член не назван ни в одном из двух неймспейсов). `presence` на уровне класса: `both`, `yarn_only`
или `mojmap_only`. `422`, если запрошенный неймспейс `from` недоступен для версии.

Замечание: `to` валидируется как имя неймспейса, но не проверяется на доступность и не влияет на
выборку — выравнивание всегда Yarn↔Mojmap.

### Байткод и исходники

| Эндпоинт                                        | Описание                                                                                                                                      |
|-------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| `GET /api/v1/bytecode/{version}/{className...}` | Дизассемблированный байткод (ASM Textifier); `namespace`, `format=text/json`                                                                  |
| `GET /api/v1/source/{version}/{className...}`   | Декомпилированный `.java` класса; `namespace=yarn/mojmap`, `format=text/json`                                                                 |
| `GET /api/v1/tokens/{version}/{className...}`   | `{source, tokens}`: каждый идентификатор `.java` резолвится в owner/name/descriptor (JavaParser); `namespace=yarn/mojmap`, `format=text/json` |

`source`: если точного совпадения имени нет, берётся единственный класс версии с таким простым
именем. Так резолвятся и короткое имя (`ZombifiedPiglin`), и класс, переехавший в другой пакет.
Поле `class` в ответе — то имя, которое реально отдано. Простых имён несколько или ни одного →
`404`, а в `message` перечислены кандидаты. `format=text` отдаёт исходник как `text/plain`,
`format=text` у `tokens` — TSV с шапкой `#startLine…declaration`, по токену на строку.

### Blame

| Эндпоинт                                     | Описание                                                                                                                                        |
|----------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------|
| `GET /api/v1/blame/{version}/{className...}` | Версия, последней менявшая каждую строку исходника класса. `lines` — по записи на строку, с первой строки, каждая запись индексирует `versions` |

`className` резолвится так же, как у `/source`. Один `git blame` по репозиторию исходников
отвечает на весь файл, поэтому используйте этот эндпоинт вместо перебора `/diff/patch` по
версиям. Версия, проиндексированная только из artifact-store (без репозитория исходников),
истории не имеет и отдаёт `404`.

В `versions` никогда нет вариантов `_unobfuscated`. Вариант — повторный проход по уже
проиндексированной сборке, так что его коммит записывает имена декомпилятора, а не изменение класса.
Каждая строка относится к версии, из которой вариант собран.

### Иерархия и ссылки

| Эндпоинт                                         | Описание                                                                                                                                                              |
|--------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `GET /api/v1/hierarchy/{version}/{className...}` | Супертипы+подтипы класса (nodes/edges, ASM-скан named-jar'а); `namespace=yarn/mojmap`                                                                                 |
| `GET /api/v1/references/{version}?q=<key>`       | Использования классов/членов (`q` = `owner` или `owner:name:descriptor`, повторяемый); `namespace=yarn/mojmap`, `releasesOnly=<bool>`                                       |
| `POST /api/v1/references/{version}`              | Тот же вызов с целями в теле `{namespace, targets[], to, releasesOnly, includeVariants, depth}`, до 2000 целей; на этом же пути принимается `QUERY`                         |
| `GET /api/v1/diff/references?from=&to=&q=`      | Как изменились места использования класса или члена между двумя версиями; `{changes: {added, removed, moved}}`                                                              |
| `POST /api/v1/exists/{version}`                  | Батч-проверка существования классов/членов; тело `{namespace, members[]}` (ключи = `owner`, `owner:name` или `owner:name:descriptor`); ответ `{results:[{key, exists, closest, reason, candidates}]}` |
| `POST /api/v1/validate?from=&to=`                | Та же проверка по диапазону плюс точка инъекции: тело `{namespace, targets[]}`, ответ — список span'ов на цель со статусами `ok`/`renamed`/`inherited`/`call_moved`/`missing` |

Каждая группа `references` несёт `resolved`. `false` означает, что группа не отвечает про цель:
у ключа нет дескриптора и он не может совпасть с `name:descriptor`, по которому построен индекс,
либо дескриптор называет член, которого индекс не знает, либо у владельца в индексе нет строки.
Тогда `candidates` перечисляет ключи, с которыми запрос совпал бы. Все три случая раньше давали
пустой `references` — то же самое, что «на это никто не ссылается», из-за чего кривой ключ читался
как факт о версии. Ключ бывает разрешим в одной версии диапазона и неразрешим в соседней, поэтому
флаг стоит на группе, а не на запросе.

Строка владельца читается один раз на группу и отвечает на обе половины, так что флаг ничего не
стоит. В обратном индексе лежит только то, на что ссылаются: отсутствие строки — это либо
отсутствие класса, либо класс, который никто не упоминает, и различить эти два случая отсюда
нельзя. Вместо того чтобы объявить ноль, эндпоинт отвечает `resolved: false`.

`references` принимает до 25 значений `q`, а параметр `to` растягивает перебор от `{version}` до
второй версии. Сам диапазон не ограничен. Ограничено то, сколько его версий не покрыто предсобранным
индексом ссылок, — не больше 25, потому что каждая такая версия стоит скана джара в 0.4 — 0.8 с и
~140 МБ. Индекс собран по релизам, поэтому `releasesOnly=true` берёт всю линию релизов одним
вызовом: 1.14 — 26.2 это 47 релизов и 48 мс. Ответят 43 из них: официальные маппинги Mojang
начинаются с 1.14.4, а версии без named-джара отвечать нечем. Без фильтра тот же диапазон — это
469 версий, 426 из
них не покрыты, и запрос отклоняется с этим же объяснением.
Строка запроса длиннее 4096 байт отбрасывается HTTP-парсером до маршрута — отсюда и предел
в 25 целей; форма `POST` вместо этого несёт до 2000 целей в теле, а на том же пути принимается
`QUERY` (RFC 10008) с тем же телом. Обе формы с телом не кэшируются, потому что кэш по URL тела не
видит. Ответ — `{namespace, results[]}`, по записи на пару (версия, цель) в форме
`{version, query, references[]}`. Индекс версии строится один раз и обслуживает все её цели,
поэтому много целей на одну версию стоят одного скана. В памяти держатся восемь индексов, первым
вытесняется тот, к которому дольше всего не обращались.

Индекс записывает владельца, записанного в инструкции вызова, а не класс, который объявляет член.
Вызов унаследованного метода несёт тот подкласс, который держит вызывающий, поэтому
`Level:getRespawnData` не отвечает ничем, а `ServerLevel:getRespawnData` отвечает 12 местами.
Обхода иерархии нет ни у одного параметра. Пустой ответ по члену читается как «ни один вызывающий
не называет этого владельца»: спросите подтипы у `/hierarchy` и повторите запрос по каждому подтипу.

У каждого места есть `count` — сколько инструкций в нём попадают в цель. Именно их `@At(ordinal =
N)` нумерует `0 .. count-1`. Вызов внутри лямбды отдаёт в `member` метод, в котором лямбда
написана, а в `synthetic` — тело, в которое её скомпилировал javac (`lambda$tick$3`), потому что
этот индекс гуляет между версиями. Вызовы внутри самого вызывающего класса индексируются, а ссылки
на методы прослеживаются через их `invokedynamic`. `depth` больше 1 обходит вызывающих у вызывающих
и добавляет `paths` — цепочки до цели, внешним кадром вперёд, не больше 200 штук.

`diff/references` группирует эти места по методу, в котором они лежат, и считает разницу между
двумя версиями. `moved` сопоставляет удалённое место с добавленным, когда оба достают ровно один и
тот же набор членов: сначала по совпадающему имени метода, затем по классу, затем единственную
оставшуюся пару. Переехавший между методами вызов сохраняет все сигнатуры, поэтому `/exists` молчит,
а `@At` ломается незаметно — ради этого случая эндпоинт и нужен. Батч-форма нужна
для половины миксина с `@At(target = ...)`: `/exists` покрывает метод, в который инжектимся, а
сигнатура может пережить версию, пока вызов внутри её тела уезжает в другой метод. `404`, если
named-jar нет ни у одной запрошенной версии.

`exists`: сканирует named-jar версии через ASM (кэш per version/namespace), поэтому дескрипторы
совпадают без ремаппинга; до 2000 ключей за запрос; `404`, если named-jar для версии отсутствует.
Единственный `POST` под `/exists`, и, как всякий `POST`, **не кэшируется** (ответ зависит от тела). Назначение —
валидация таргетов миксинов/shadow при апдейте мода одним вызовом.

У промахнувшегося ключа поле `closest` содержит ближайшее объявление в той же форме ключа, а
`reason` — чем оно отличается:

- `inherited`: точно такую сигнатуру объявляет супертип, то есть вызов в рантайме по-прежнему
  резолвится. Таргет `@At` валиден, а `@Shadow` должен называть супертип.
- `descriptor`: владелец объявляет это имя с другим дескриптором **того же вида**, то есть
  сигнатура поменялась. В `closest` лежит дескриптор, который есть у версии.
- `kind`: владелец объявляет это имя полем там, где спросили метод, или наоборот. `closest`
  называет это объявление, но подставить его вместо ключа нельзя. Отличаются они по одному
  дескриптору: у метода он начинается со скобки, у поля нет. На 26.2 так отвечает
  `Level:getBlockState`, если спросить его полем.

Кандидат того же вида выигрывает у кандидата другого вида, и поэтому `descriptor` означает именно
то, что написано. `CommandSourceStack` на 26.2 объявляет и поле `permissions`, и метод
`permissions()`, и на ключ-метод отвечает метод.

Оба поля пусты, когда версия не знает такого имени под этим владельцем, и когда `exists` = true.
Без них голый `false` читается одинаково и при смене дескриптора, и при переезде члена в супертип,
и при исчезновении имени, а выяснение стоило чтения `/source` на каждый ключ.

Ключ без дескриптора — это резолв, а не проверка существования. Совпасть с `owner:name:descriptor`
он не может, поэтому вместо голого `false` возвращается `candidates`: все объявления под этим
именем, в форме ключа, прочитанные из того же джара, без ранжирования и без фаззи-поиска. Одна
запись — канонический ключ для `owner#name`, несколько — его перегрузки, а `closest` и `reason`
остаются пустыми. Раньше вместо этого приходилось брать `results[0]` из `/search`.

## Общие правила контракта

- **Неймспейсы:** `yarn`, `mojmap`, `intermediary`, `obfuscated` (алиас `obf`). Где какие допускаются — см. таблицы выше.
- **Версия по умолчанию** (search/translate) — последний `release` по semver-порядку.
- **Ошибки** — единый `ApiError { error, message, status }`, где `status` дублирует HTTP-код:
  `400 invalid_query` (валидация), `404 not_found`, `422 namespace_unavailable` (версия не имеет запрошенного неймспейса).
- **Форматы ответов:** JSON по умолчанию; `bytecode/source/tokens?format=text` → `text/plain`; `diff` патч (`format=patch/git`) → `text/x-diff`.
- **`hasIntermediary`** — версия имеет intermediary-имена, а не отдельный intermediary-файл. Yarn tiny v2
  устроен как `official->intermediary->named`, поэтому любая yarn-версия отдаёт intermediary.
  Unobfuscated-релиз, который yarn не покрывает, отдаёт intermediary только при заданном
  `sources.unobfuscated-intermediary-mappings`.
- **`hasMojmap`** — у unobfuscated-релизов тоже true. Своих маппингов они не публикуют, но имена
  Mojang уже лежат в самом jar, поэтому неймспейс `official` и есть неймспейс `mojmap`: на таких
  версиях `obfuscated` и `mojmap` возвращают одно и то же имя.
- **Rate limit:** 200 запросов / 60 с на группы `/api/v1` (мета-эндпоинты не лимитируются).

### Поведенческие замечания (важно для агентов)

- `search.totalResults` — это размер **текущей страницы**, а не общее число совпадений.
- `diff*` с несуществующей версией возвращает **200** с пустым/нулевым результатом (не 404).
- `translate` и `compare` с несуществующей версией возвращают **404**, не 422.
- `compare`: параметр `to` валидируется, но на выборку не влияет — выравнивание всегда Yarn↔Mojmap;
  `from` выбирает колонку для поиска класса и определяет проверку 422.
- `/diff/files`: `context`/`limit`/`function` читаются только при `format=patch/git`; при `format=json` игнорируются.

## Что хранит индекс

SQLite-индекс (собирается `index`, открывается `serve` как RO): `versions` (метаданные + semver-порядок + counts)
и унифицированные obf-ключённые строки `classes`/`methods`/`fields` (с `presence ∈ {both, yarn_only, mojmap_only}`).
**Не хранит** декомпилированный исходник, байткод и git-блобы — они читаются по требованию из read-only стора.

Ссылки отвечаются из третьего файла, `mappinglens-refs.db`: там по строке на класс каждой пары
(версия, namespace), а в строке — кто ссылается на каждый его член, сжатый deflate. Без этого файла
сервер сканирует весь named-jar версии при первом вопросе о ней: 0.4 — 0.8 с и ~140 МБ в памяти,
пока индекс лежит в кэше. Чтение строки стоит 0.7 мс на новом соединении и 0.1 мс на прогретом, а в
памяти не оседает ничего: на проверках выше живая куча осталась 12 МБ там, где путь со сканом дошёл
до 584 МБ. Строка на класс, а не на член, потому что класс — это единица, которую спрашивают, и
потому что такие блобы жмутся в 6.8 раза против 2.7 у блобов размером с член.

`index` собирает файл по релизам: 90 пар (версия, namespace), 1.0 ГБ, 57 с. `-refs=all` собирает по
всем версиям (10.3 ГБ, 11 минут), `-refs=none` пропускает шаг. Контейнер по умолчанию передаёт
`-refs=all`, через переменную `REFS`. Собранная пара пропускается при
следующих запусках, потому что джар за ней не меняется. Файл необязателен: версия, которой в нём
нет, отвечается сканом, поэтому частичный файл — рабочий файл, а сервер без файла работает как
раньше.

Имена ищутся во втором файле, `mappinglens-search.db`: там лежит по одной contentless FTS5-таблице
на версию, с именем `search_v<row id версии>`. FTS5 отвечает на префиксный терм так: сливает
doclist'ы всех термов с этим префиксом по всей таблице, и только потом сужает по rowid. Поэтому
одна таблица на все версии читала 5.5 млн постингов на `get*`, чтобы отранжировать 13697 строк
нужной версии. Отдельная таблица на версию отвечает за 24 мс вместо 959 и стоит на 2% больше байт.
Таблицы contentless, потому что сервер не читает из них ни одного имени — только какая строка
совпала и её ранг bm25: идентификатор строки лежит в rowid, вид элемента — в двух младших битах.
На 52.3 млн строк весь файл занимает 5.3 ГБ против 14.9 ГБ у одной таблицы, которую он заменил.
Файл отдельный, потому что 526 виртуальных таблиц добавляют около 2600 строк в `sqlite_master`,
а сервер открывает соединение на каждый запрос: разбор этих строк стоит 7 мс, которые иначе
платили бы все эндпоинты.

### Члены unobfuscated-релиза

Intermediary называет переопределяющий метод только в том классе, который объявляет его первым:
дальше по иерархии имя наследуется и заново не пишется. У обфусцированного релиза это незаметно,
потому что его mojmap-tiny перечисляет каждый объявленный член и закрывает пробел. У
unobfuscated-релиза mojmap-tiny нет, поэтому разбор одних маппингов не даёт ему оверрайдов вообще.

Для таких релизов индексатор читает джарник самой версии и добавляет члены, которых нет в
маппингах. Члены, известные маппингам, сохраняют свои yarn- и intermediary-имена; известные только
джарнику попадают как mojmap-only, чем они и являются. Классы в обоих случаях берутся из маппингов.

Масштаб пробела до исправления, на одном билде, проиндексированном обоими путями: у `1.21.11` было
89 606 методов против 56 986 у `1.21.11_unobfuscated`, а `/diff` между ними показывал 32 355
удалённых методов при полном отсутствии изменений. Поля расходились в пределах 1% (45 679 против
45 263), потому что поле не переопределяется. На `/diff` с 1.21.11 на 26.1 тот же пробел давал
49 из 62 членов, помеченных удалёнными у `ServerLevel`, при том что в 26.1 они объявлены.

Индекс, собранный до исправления, несёт пробел, пока затронутые версии не переиндексированы.
