# MappingLens — Описание сервиса

*(English version: [SERVICE.md](SERVICE.md))*

MappingLens — stateless read-only сервис для поиска, перевода, сравнения и инспекции маппингов
Minecraft (Yarn / Mojmap / Intermediary / Obfuscated).

- **`index`** — offline-индексатор, единственный писатель SQLite-индекса.
- **`index-resources`** — собирает необязательный индекс ресурсов.
- **`serve`** — stateless HTTP-сервер (Ktor/Netty), открывает индекс только на чтение.
- **`frontend/`** — браузерный explorer (React + Vite) поверх REST API.

Сервер ничего не декомпилирует и не мутирует: исходники и байткод читаются по требованию из
read-only GitCraft-стора, индекс открывается с `PRAGMA query_only=ON`.

| Версии                 | Проиндексированные версии с флагами неймспейсов, counts и semver-порядком           |
| Обозреватель ресурсов  | Все ресурсы Minecraft всех версий с 1.14, из клона `misode/mcmeta`. Опционально     |

| Frontend explorer      | Браузерный UI поверх маппингов и ресурсов                                           |

## Требования

- **JDK 21** (Gradle toolchain). Стек: Kotlin 2.2.20, Ktor 3.2.3, Exposed 0.56, sqlite-jdbc.
- **Node.js**, для frontend.
- **Данные на диске:**
  - `index` читает `artifact-store` (с `mappings/`, `mc-versions/`, `decompiled/<ver>/`,
    `remapped-mc/<ver>/`), а также `yarn`, `mojmap` и `intermediary`.
  - `serve` нужен индекс по пути `database.path` и поисковый индекс рядом с ним
    (`mappinglens.db` даёт `mappinglens-search.db`); без любого из них сервер не стартует.
    Репозитории исходников на старте не нужны, но `diff`, `bytecode` и `source` читают jar'ы из
    `artifact-store` во время запроса.
  - `/openapi.*` и `/docs` нужен ресурс `openapi/mappinglens-api.yaml` на classpath.
  - Обозревателю ресурсов нужен клон `misode/mcmeta` по пути `resources.repo` и его индекс
    (`mappinglens-resources.db`), который собирает `index-resources`. Без них эндпоинты
    `/api/v1/resources` отвечают `404 resources_disabled`.

> **Совместимость схемы.** Индекс без колонок `versions.sort_index`, `classes.presence` или
> `versions.class_count` даёт `500 no such column: ...`. Один прогон `index` добавляет все колонки,
> а `dev/migrate-version-counts.sql` добавляет и заполняет счётчики без пересборки. Индекс,
> собранный до `mappinglens-search.db`, несёт старую таблицу `search_index` внутри основного файла:
> один прогон `index` строит потаблично по версиям и удаляет её, после чего `VACUUM` возвращает
> 14.9 ГБ файловой системе.

## Конфигурация

HOCON-файл `application.conf` создаётся из встроенного шаблона при первом запуске. Все пути
переопределяются переменными окружения.

| Ключ                                                     | По умолчанию          | Env / CLI                               | Назначение                                                                                |
|----------------------------------------------------------|-----------------------|-----------------------------------------|-------------------------------------------------------------------------------------------|
| `ktor.deployment.host`                                   | `0.0.0.0`             | `HOST`, `-host`                         | Адрес привязки                                                                            |
| `ktor.deployment.port`                                   | `8080`                | `PORT`, `-port`                         | Порт                                                                                      |
| `mappinglens.database.path`                              | `data/mappinglens.db` | `MAPPINGLENS_DB_PATH`                   | SQLite-индекс (serve — RO, index — пишет)                                                 |
| `mappinglens.sources.artifact-store`                     | `data/artifact-store` | `MAPPINGLENS_ARTIFACT_STORE`            | Корень стора                                                                              |
| `mappinglens.sources.yarn-repo`                          | `data/yarn`           | `MAPPINGLENS_YARN_REPO`                 | Источник Yarn (только индексация)                                                         |
| `mappinglens.sources.mojmap-repo`                        | `data/mojmap`         | `MAPPINGLENS_MOJMAP_REPO`               | Источник Mojmap (только индексация)                                                       |
| `mappinglens.sources.intermediary-mappings`              | `data/intermediary`   | `MAPPINGLENS_INTERMEDIARY`              | Источник Intermediary (только индексация)                                                 |
| `mappinglens.sources.unobfuscated-intermediary-mappings` | `""` (выкл.)          | `MAPPINGLENS_UNOBFUSCATED_INTERMEDIARY` | Источник Intermediary для unobfuscated-релизов, отдельный репозиторий (только индексация) |
| `mappinglens.search.max-results`                         | `200`                 | —                                       | Верхняя граница `limit` для поиска                                                        |
| `mappinglens.search.default-results`                     | `50`                  | —                                       | `limit` по умолчанию                                                                      |
| `mappinglens.indexing.initial-versions`                  | `[]` (все)            | —                                       | Версии, которые собирает `index`; **игнорируется `serve`**                                |
| `mappinglens.indexing.mappings`                          | `"yarn,mojmap"`       | `MAPPINGS`                              | Какие именованные маппинги читает `index`: `yarn`, `mojmap` или оба                       |
| `mappinglens.indexing.only-releases`                     | `false`               | `ONLY_RELEASES`                         | Индексировать только стабильные релизы                                                    |
| `mappinglens.resources.repo`                             | `""` (выкл.)          | `MAPPINGLENS_MCMETA_REPO`               | Клон `misode/mcmeta`; пустое значение выключает обозреватель ресурсов                     |
| `mappinglens.cache.reference-indexes`                    | `8`                   | `CACHE_REFERENCE_INDEXES`               | Сколько reverse-reference индексов держать в памяти, 34-61 МБ каждый                       |
| `mappinglens.cache.declarations`                         | `4`                   | `CACHE_DECLARATIONS`                    | Графы объявлений в памяти, 10-19 МБ каждый, только для версий, которых нет в decl-индексе  |
| `mappinglens.cache.name-maps`                            | `4`                   | `CACHE_NAME_MAPS`                       | Карты obf-в-именованное в памяти, 17-32 МБ на пару (версия, namespace)                     |
| `mappinglens.cache.symbol-solvers`                       | `4`                   | `CACHE_SYMBOL_SOLVERS`                  | Symbol solver'ы JavaParser. Ограничивает только число записей, **не** память (см. ниже)    |
| `mappinglens.cache.tokens`                               | `500`                 | `CACHE_TOKENS`                          | Списки токенов, по одному на (версия, класс, namespace), 40 КБ-970 КБ каждый               |
| `mappinglens.cache.paths`                                | `2000`                | `CACHE_PATHS`                           | Разрешённые пути к jar-ам и списки библиотек, 19 КБ на версию                              |

Размеры выше — retained heap одной записи, замерено на 1.16.5, 1.21.4 и 1.21.11. `reference-indexes`
и `declarations` остаются пустыми для всех версий, покрытых `mappinglens-refs.db` и
`mappinglens-decl.db`, так что полный индекс держит оба на нуле.

`symbol-solvers` — исключение, и никакое число записей этого не чинит. Солвер начинает с 12 МБ и
растёт по мере резолва классов: 57 МБ после 240 классов, без выхода на плато в этом диапазоне. Обход
целой версии через `/tokens` стоит порядка 0.5-1 ГБ. Вытеснение не возвращает ничего: JavaParser
держит каждый солвер в `JavaParserFacade.instances`, статическом `WeakHashMap`, значение которого
ссылается на собственный ключ, поэтому ни одна запись этой карты никогда не собирается. Давай `serve`
heap под то число версий, которое он отдаёт через `/tokens`, и перезапускай, чтобы освободить память.

`resources.repo` — весь переключатель обозревателя ресурсов, а гранулярность задаёт набор веток в
клоне: индексатор читает `assets`, `diff`, `registries` и `atlas` и пропускает те, которых нет.
Все четыре стоят 2.1 GiB, из них `assets` — 1.5 GiB, `atlas` — 575 MiB. Ветку добавляют позже через
`git remote set-branches --add origin <ветка>` и повторный fetch.

`indexing.only-releases` оставляет версии с типом release. Pre-релизы, release candidate,
первоапрельские версии, combat-снапшоты и варианты `_unobfuscated` уходят со снапшотами.
`indexing.mappings` исключает именованный маппинг из чтения маппингов, из сканирования исходников и
из reference- и decl-индексов, и `/versions` отдаёт это пространство имён как отсутствующее.

Блок `cache` — это все ограничения на то, что сервер держит в памяти между запросами. Каждый из
этих кэшей ключуется на версию, поэтому растёт от числа версий, по которым ходит клиент, а не от
частоты запросов: без ограничения одни только шестнадцать reference-индексов заняли 1557 МБ против
4 ГБ кучи, которые задаёт compose-файл. Числа разные, потому что разные и записи — от разрешённого
пути к jar-у до reference-индекса на 61 МБ, так что увеличение счётчика меняет кучу на работу по
пересборке записи. Больше не держится ничего: соединения с индексами открываются на запрос.

**Плагины Ktor:** ContentNegotiation (kotlinx JSON), CallLogging, CORS (`anyHost`, GET и POST,
`Content-Type`), RateLimit (200 запросов / 60 с на `/api/v1`), StatusPages
(`IllegalArgumentException` → `400 invalid_query`, прочее → `500 internal_error`) и плагин
кэш-заголовков для успешных `/api/v1`-ответов.

## Запуск

```sh
# 1. Собрать read-only индекс (единственный писатель БД).
./gradlew run --args="index"

# 1a. Пересобрать только указанные версии. `-versions` перекрывает `indexing.initial-versions`;
#     уже проиндексированная версия пересобирается только вместе с `-force`.
./gradlew run --args="index -force -versions=1.21.4,26.2"

# 1b. Собрать индекс ресурсов (опционально). Нужен mappinglens.resources.repo.
#     `-fts=content` пропускает индекс переводов, `-fts=none` — оба индекса.
./gradlew run --args="index-resources"

# 2. Запустить сервер. `serve` — команда по умолчанию, если первый аргумент
#    отсутствует или начинается с '-'.
./gradlew run --args="serve"            # слушает :8080

# 3. Frontend (dev): Vite проксирует /api -> http://localhost:8080
cd frontend
npm install
npm run dev                              # http://localhost:5173
npm run build                            # статика в dist/
```

`main()` берёт `args[0]` как подкоманду только если она не начинается с `-`. Любой токен, кроме
`index`, `index-resources` и `serve`, печатает usage и выходит с кодом 2.

Прод-вариант: задеплоить `dist/` как статику и проксировать `/api` на работающий `serve`.

## Docker

Два сервиса. `mappinglens` держит `serve` запущенным и сам достраивает данные: GitCraft пополняет
артефакт-стор и репозитории исходников, `index` обновляет индекс. `frontend` отдаёт собранный бандл
через nginx, который проксирует `/api/` на `http://mappinglens:8080`.

```sh
docker compose -f docker/docker-compose.yml up -d --build
```

| Сервис        | Порт на хосте                        | Dockerfile                   |
|---------------|--------------------------------------|------------------------------|
| `mappinglens` | `8080` — API и Swagger UI на `/docs` | `docker/Dockerfile`          |
| `frontend`    | `3000` — UI                          | `docker/Dockerfile.frontend` |

В образе API: fat jar (JDK 21), GitCraft (JDK 25), чекауты `FabricMC/intermediary`,
`RelativityMC/intermediary`, `FabricMC/yarn`, `RelativityMC/yarn` и пресеты GitCraft. Контекст
сборки у обоих образов — корень проекта, тома объявлены в compose-файле.

| Каталог в томе `/data`       | Что лежит                                                        |
|------------------------------|-------------------------------------------------------------------|
| `artifact-store/`            | Артефакт-стор GitCraft                                            |
| `repos/yarn`, `repos/mojmap` | Git-репозитории декомпилированных исходников                      |
| `index/mappinglens.db`       | SQLite-индекс                                                     |
| `mcmeta/`                    | Клон `misode/mcmeta`, если `MCMETA_BRANCHES` не пуста             |
| `state/`                     | Маркеры цикла обновления, в том числе снимок стора `store.files`  |
| `gradle/`                    | Gradle home для прогонов GitCraft                                 |

Цикл `docker/entrypoint.sh`, интервал `UPDATE_INTERVAL_SECONDS`:

1. Обновляет четыре чекаута и считает один отпечаток по их refs.
2. Новая версия в манифесте Mojang запускает первый пресет из `MAPPINGS`. GitCraft собирает всё,
   чего нет в сторе, этим же заполняется и пустой стор.
3. Опубликованный билд yarn выше того, что лежит в сторе, либо его отсутствие на диске запускает
   пресет `yarn`.
4. Индексация — единственный шаг, который индексирует, и смотрит он на стор, а не на код возврата
   сборки: сначала `index -force -versions=<...>` по версиям, чьи файлы разошлись со снимком
   `state/store.files`, затем обычный `index` по версиям, которых нет в базе. Снимок пишется только
   после успеха.
5. Обозреватель ресурсов, если `MCMETA_BRANCHES` не пуста. Сдвинувшийся tip ветки пересобирает
   `index/mappinglens-resources.db` целиком.
6. Изменение любого из индексов рестартует `serve`, один раз за цикл.

Сравниваются все версии, а не только свежие. Если ни один mapping-репозиторий не двигался и набор
несобираемых версий не изменился, прогон GitCraft пропускается.

| Переменная                | По умолчанию                       | Назначение                                                        |
|---------------------------|------------------------------------|--------------------------------------------------------------------|
| `UPDATE_INTERVAL_SECONDS` | `3600`                             | Пауза между проверками                                            |
| `MAPPINGS`                | `mojmap yarn`                      | Какие маппинги собирать и индексировать                           |
| `ONLY_RELEASES`           | `false`                            | Только стабильные релизы (GitCraft `--only-stable`)               |
| `REFS`                    | `all`                              | Охват reverse-reference индекса: `all`, `releases` или `none`     |
| `DECL`                    | `all`                              | Охват decl-индекса: `all`, `releases` или `none`                  |
| `MCMETA_BRANCHES`         | `assets diff registries atlas`     | Ветки mcmeta; пустое значение выключает обозреватель ресурсов     |
| `MCMETA_FTS`              | `all`                              | Охват полнотекстовых таблиц ресурсов: `all`, `content` или `none` |
| `MCMETA_URL`              | `https://github.com/misode/mcmeta` | Откуда берётся клон                                               |
| `PORT`                    | `8080`                             | Порт `serve`                                                      |
| `MAPPINGLENS_*`           | пути внутри `/data`                | Те же переменные, что и вне контейнера                            |
| `GITCRAFT_JAVA_OPTS`      | —                                  | Опции JVM для прогона GitCraft                                    |
| `INDEX_JAVA_OPTS`         | —                                  | Опции JVM для `index`                                             |
| `SERVE_JAVA_OPTS`         | —                                  | Опции JVM для `serve`                                             |

Build-args `GITCRAFT_REPO` и `GITCRAFT_REF` указывают, откуда брать GitCraft.

> На пустом томе первый прогон строит все версии с нуля и занимает дни, `serve` поднимется только
> после появления индекса. Готовый артефакт-стор монтируется поверх `/data/artifact-store`.

## Эндпоинты

Базовый префикс — `/api/v1`. Все эндпоинты `GET`, если не указано иное. `{className...}` и
`{name...}` — catch-all: остаток пути склеивается в internal-имя класса.

### Мета (без rate-limit)

| Эндпоинт            | Описание                                        |
|---------------------|-------------------------------------------------|
| `GET /`             | Текстовый указатель на `/docs` и `/openapi.json` |
| `GET /health`       | Liveness, отвечает `ok`                         |
| `GET /openapi.json` | OpenAPI 3.1 как JSON                            |
| `GET /openapi.yaml` | OpenAPI 3.1 в YAML                              |
| `GET /docs`         | Swagger UI                                      |

### Версии

| Эндпоинт                         | Описание                                                                   |
|----------------------------------|-----------------------------------------------------------------------------|
| `GET /api/v1/versions`           | Все версии с флагами неймспейсов и counts, порядок semver (новые сверху)   |
| `GET /api/v1/versions/{version}` | Метаданные одной версии (`404 version_not_found`)                          |

**Вариант** — повторная индексация билда, который уже есть в списке под собственным id
(`<id>_unobfuscated`, из предеобфусцированного джарника Mojang). Поле `variantOf` называет исходный
билд и равно `null` у самостоятельной версии. Варианты не попадают в листинг, в перебор `/history`
и в выбор версии по умолчанию: один билд, показанный дважды, читается как две версии. Вернуть их
можно параметром `includeVariants=true` в `/versions`, `/history` и `/references`. По имени вариант
отвечает всегда.

### Поиск

| Эндпоинт             | Описание                                                     |
|----------------------|--------------------------------------------------------------|
| `GET /api/v1/search` | FTS-поиск классов, методов и полей в одной версии            |

Параметры: `q` (обяз., принимает формы `Owner#member`, `Owner.member`, `Owner/member`), `version`
(по умолч. последний release), `type` (`class/method/field/all`), `namespace`
(`yarn/mojmap/intermediary/all`), `limit` (1–200, по умолч. 50), `offset`, `exact`,
`includeSynthetic` (по умолч. `false`).

Строка-член несёт дескриптор трижды: `intermediaryDescriptor` — как его хранит индекс, плюс
`yarnDescriptor` и `mojmapDescriptor`, переписанные через классы этой версии. Именно именованные два
сверяет `/exists`, поэтому ключ, собранный из строки поиска, уходит туда без перевода. Неймспейс,
имени в котором у строки нет, дескриптора не получает, а тип, которого версия не называет, остаётся
как есть. `/diff` отдаёт только intermediary.

`score` лежит от `0` до почти `1`, больше значит лучше, строки приходят от лучшей к худшей. Значение
выводится из ранга bm25 конкретного запроса и сравнивает результаты одного вызова.

`includeSynthetic` решает, отдавать ли тела лямбд; у оставленной строки стоит `synthetic: true`.

### Перевод

| Эндпоинт                                | Описание                                                                              |
|-----------------------------------------|---------------------------------------------------------------------------------------|
| `GET /api/v1/translate`                 | Перевод имени между неймспейсами (`name`, `from`, `to`, `version?`, `type=auto`)      |
| `GET /api/v1/translate/class/{name...}` | Шорткат перевода класса (`from`/`to` по умолч. `yarn` → `mojmap`)                     |
| `POST /api/v1/translate/{version}`      | Батч-перевод ключей; тело `{from, to, keys[]}`; ответ `{results:[{key, translated, type, intermediary}]}` |

Батч-форма принимает те же ключи, что `/exists` (internal-имя класса либо `owner:name:descriptor`),
записанные в `from`, до 2000 за запрос. `translated` — целый ключ в `to` вместе с дескриптором,
поэтому результат отправляется в `/exists/{version}` как есть.

Дескрипторы переводятся потипно через таблицу классов, опорой служит official-вариант. Тип, которого
версия не знает (класс JDK), остаётся как есть. Ключ без дескриптора разрешается только при
единственном совпадении имени: у перегруженного имени `translated` будет `null`.

### Diff

| Эндпоинт                 | Описание                                                                                                  |
|--------------------------|-----------------------------------------------------------------------------------------------------------|
| `GET /api/v1/diff`       | Символьный diff (added/removed/renamed классов, методов, полей) + summary                                 |
| `GET /api/v1/diff/files` | Список изменённых файлов (`format=json`) или raw-патч (`format=patch/git`)                                |
| `GET /api/v1/diff/patch` | Unified/git-патч исходников (фильтры `path`/`file`/`function`, `context`, `limit`) или JSON с метаданными |

Параметры: `from`, `to` (обяз.); `namespace` (для `/diff` — `yarn/mojmap/intermediary`, для
`/diff/files` и `/diff/patch` — только `yarn/mojmap`); `type`, `package`, `class`, `changeType`,
`limit`.

- `package` — префикс пакета, читается в `namespace`. `class` — ровно один класс по внутреннему
  имени, перечисляет добавленные, удалённые и переименованные члены с `owner` и `descriptor`.
  `class` приоритетнее `package`.
- `/diff/files?format=patch` и `/diff/patch` принимают `ignoreWhitespace` (по умолч. `false`):
  схлопывает ханки, отличающиеся только косметикой декомпилятора. Патчи минимальны по построению
  (Myers O(ND)).

### История по версиям

| Эндпоинт                      | Описание                                                                                |
|-------------------------------|-----------------------------------------------------------------------------------------|
| `GET /api/v1/history?q=<key>` | Один класс или член по всем версиям: список диапазонов (`spans`) с одинаковым ответом   |

Параметры: `q` (обяз., повторяемый до 50: internal-имя класса или `owner:name`), `namespace`
(по умолч. `mojmap`), `from`/`to` (порядок границ не важен, неизвестная версия → `404`),
`releasesOnly`, `includeVariants`. Третий сегмент `:descriptor` принимается ради совместимости, но
в отборе не участвует. Граница может называть версию, которую перебор потом пропустит.

Ответ — `{namespace, results[]}`, по записи на каждый `q` в порядке запроса, поле `query` повторяет
исходную строку дословно. `type` = `class`/`method`/`field`/`unknown`. Каждый `span` — диапазон
подряд идущих версий с одинаковым ответом: `from`, `to`, `versions`, `present`. Для класса заполнены
`intermediary`/`yarn`/`mojmap`, для члена — `owner` и `members[]`, по записи на перегрузку.

- Класс отслеживается по intermediary-имени самого нового совпадения, поэтому переименование и
  переезд в другой пакет остаются одной историей. Отсюда же следует, что два написания одного члена
  дают одинаковые спаны и разные значения `query`, а имя конкретной версии лежит в `members[]`.
- Unobfuscated-релизы (всё после 1.21.11) своих маппингов не содержат. С заданным
  `sources.unobfuscated-intermediary-mappings` intermediary у них есть, состояние индекса видно по
  `hasIntermediary` в `/versions`. Без этого источника класс дополнительно ищется в ближайшей
  предыдущей версии с intermediary по простому имени, поэтому класс, переименованный (а не
  переехавший) после 1.21.11, историю до 1.21.11 не получит. Два имени, живущие в одной версии, не
  связываются никогда.
- Именованные дескрипторы в индексе не хранятся, поэтому смена сигнатуры видна только по
  `members[].intermediaryDescriptor` и только на версиях с intermediary.
- `present: false` с непустым `owner` — класс жив, а члена с таким именем он не объявляет;
  `owner: null` — исчез класс.
- `present: false` с `reason: "inherited"` — член объявлен в супертипе, и вызов по-прежнему
  разрешается; `declaredIn` называет супертип, `members[]` описывает его объявление.
- `type: "unknown"` тоже несёт span'ы: такого члена в индексе нет нигде, а span'ы говорят, на каких
  версиях.
- `/history` смотрит в индекс маппингов, `/exists` — в джарник, под который собран мод. При
  расхождении прав джарник.

### Хэш тела метода

| Эндпоинт                       | Описание                                                                            |
|--------------------------------|-------------------------------------------------------------------------------------|
| `GET /api/v1/bodyhash?q=<key>` | Тело метода, хэшированное по каждой версии диапазона, соседи с общим хэшем слипаются |

Параметры: `q` (обяз., повторяемый до 50: `owner:name` или `owner:name:descriptor`), `namespace`
(`yarn`/`mojmap`, по умолч. `mojmap`), `from` и `to` (оба обязательны), `releasesOnly`,
`includeVariants`, `normalize` (`named` либо `intermediary`). Диапазон ограничен 60 версиями, счёт
идёт после фильтров.

Это ответ на вопрос «менялось ли поведение между A и B», которого не даёт `/diff/patch`: тот
работает по декомпилированному исходнику и показывает косметику декомпилятора как изменение. Ответ —
`{namespace, normalize, results[]}`, запись `{query, spans[]}`, span `{from, to, versions, hash}`.
`hash` пуст там, где метода в версии нет. Без дескриптора все перегрузки имени хэшируются вместе,
отсортированные.

Хэш покрывает инструкции, метки переходов, таблицу try/catch и размеры фрейма. `SKIP_DEBUG` убирает
номера строк и имена локальных переменных, поэтому одна пересборка хэш не двигает.
`normalize=intermediary` сначала переименовывает типы классов, и это позволяет хэшу пережить
переименование класса или переезд пакета; имена членов остаются как их пишет неймспейс.

Два потолка. Тело лямбды — отдельный метод, и обход в него не заходит, поэтому изменение внутри
лямбды хэш объемлющего метода не двигает. И у unobfuscated-версии нет intermediary-имён, поэтому
границу обфускации span не переживает ни в одном режиме.

### Матрица целей миксина

| Эндпоинт                | Описание                                                    |
|-------------------------|-------------------------------------------------------------|
| `POST /api/v1/validate` | Набор целей миксина, проверенный по каждой версии диапазона |

Параметры строки запроса: `from` и `to` (оба обязательны), `releasesOnly`, `includeVariants`.
Диапазон ограничен 60 версиями, счёт идёт после фильтров. Тело —
`{namespace, targets: [{id, owner, method, descriptor?, at?}]}`, до 50 целей, где `at` — это
`{value, target}`, `value` равно `INVOKE` или `FIELD`, а `target` — полный `owner:name:descriptor`.
Без `descriptor` берутся все перегрузки, без `at` проверяется одна сигнатура.

Ответ — `{namespace, results[]}`, запись `{id, spans[]}`, span
`{from, to, versions, status, atCount, closest, movedTo}`. Пять статусов:

- `ok`: метод на месте, и если задан `at`, то и инструкция на месте. `atCount` говорит, сколько раз,
  и это те номера, которые `@At(ordinal = N)` считает от 0 до `atCount-1`.
- `renamed`: имя есть, дескриптор другой, нужный лежит в `closest`.
- `inherited`: член объявлен в супертипе. Вызов разрешается, но миксин применяется к классу, где
  метод объявлен, поэтому цель должна называть супертип — его и даёт `closest`.
- `call_moved`: метод на месте, инструкции из `at` в теле нет. `movedTo` называет метод, где вызов
  теперь лежит.
- `missing`: ни метода, ни близкого объявления. `movedTo` заполняется, если ровно один другой метод
  класса держит этот вызов.

`call_moved` — то, ради чего эндпоинт и сделан: уехавший из тела вызов не трогает ни одну сигнатуру,
поэтому `/exists` молчит, а точка инъекции ломается тихо.

Два потолка. Вызов, уехавший в лямбду, читается как `call_moved`, и `movedTo` называет
`lambda$stopSleeping$9` буквально, потому что именно это цель для миксина. И значение `@At`, которое
не называет одну инструкцию (`HEAD`, `RETURN`, `CONSTANT`), отклоняется, а не угадывается.

### Compare

| Эндпоинт                                       | Описание                                                         |
|------------------------------------------------|------------------------------------------------------------------|
| `GET /api/v1/compare/{version}/{className...}` | Таблица соответствия членов Yarn/Mojmap для одного класса        |

Параметры: `from` (по умолч. `yarn` — выбирает колонку поиска класса и проверку доступности),
`to` (по умолч. `mojmap`; валидируется, но на доступность не проверяется и на выборку не влияет,
выравнивание всегда Yarn/Mojmap).

Ответ: obf-ключённая таблица членов, включая члены только с одной стороны. Исходники не читаются.
`status` на уровне члена: `matched`, `yarnOnly`, `mojmapOnly`, `unmappedYarn`, `synthetic`,
`initializer` или `unmapped`. `presence` на уровне класса: `both`, `yarn_only` или `mojmap_only`.
`422`, если запрошенный неймспейс `from` недоступен для версии.

### Байткод и исходники

| Эндпоинт                                        | Описание                                                                                     |
|-------------------------------------------------|-----------------------------------------------------------------------------------------------|
| `GET /api/v1/bytecode/{version}/{className...}` | Дизассемблированный байткод (ASM Textifier); `namespace`, `format=text/json`                  |
| `GET /api/v1/source/{version}/{className...}`   | Декомпилированный `.java`; `namespace=yarn/mojmap`, `format=text/json`                        |
| `GET /api/v1/tokens/{version}/{className...}`   | `{source, tokens}`: идентификаторы, резолвнутые в owner/name/descriptor; `namespace`, `format` |

`source`: если точного совпадения имени нет, берётся единственный класс версии с таким простым
именем, чем резолвятся и короткое имя (`ZombifiedPiglin`), и класс, переехавший в другой пакет. Поле
`class` в ответе — то имя, которое реально отдано. Простых имён несколько или ни одного → `404`, а в
`message` перечислены кандидаты. `format=text` у `tokens` — TSV с шапкой из `#`, по токену на строку.

### Blame

| Эндпоинт                                     | Описание                                                       |
|----------------------------------------------|-----------------------------------------------------------------|
| `GET /api/v1/blame/{version}/{className...}` | Версия, последней менявшая каждую строку исходника класса       |

`lines` — по записи на строку, с первой строки, каждая запись индексирует `versions`. `className`
резолвится так же, как у `/source`. Один `git blame` отвечает на весь файл, поэтому используйте этот
эндпоинт вместо перебора `/diff/patch`. Версия без репозитория исходников отдаёт `404`.

В `versions` никогда нет вариантов `_unobfuscated`: каждая строка относится к версии, из которой
вариант собран.

### Иерархия и ссылки

| Эндпоинт                                         | Описание                                                                                                                  |
|--------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| `GET /api/v1/hierarchy/{version}/{className...}` | Супертипы и подтипы класса (nodes/edges); `namespace=yarn/mojmap`                                                          |
| `GET /api/v1/references/{version}?q=<key>`       | Использования классов и членов (`q` = `owner` или `owner:name:descriptor`, повторяемый); `namespace`, `releasesOnly`, `to`, `depth` |
| `POST /api/v1/references/{version}`              | Тот же вызов с целями в теле, до 2000; на этом же пути принимается `QUERY`                                                  |
| `GET /api/v1/diff/references?from=&to=&q=`       | Как изменились места использования класса или члена между двумя версиями; `{changes: {added, removed, moved}}`             |
| `POST /api/v1/exists/{version}`                  | Батч-проверка существования; тело `{namespace, members[]}`; ответ `{results:[{key, exists, closest, reason, candidates}]}` |
| `POST /api/v1/validate?from=&to=`                | Та же проверка по диапазону плюс точка инъекции (см. «Матрица целей миксина»)                                              |

Каждая группа `references` несёт `resolved`. `false` означает, что группа не отвечает про цель: у
ключа нет дескриптора и он не может совпасть с `name:descriptor`, по которому построен индекс, либо
дескриптор называет член, которого индекс не знает, либо у владельца в индексе нет строки. Тогда
`candidates` перечисляет ключи, с которыми запрос совпал бы. Иначе все три случая читались бы как
«на это никто не ссылается». Ключ бывает разрешим в одной версии диапазона и неразрешим в соседней,
поэтому флаг стоит на группе.

`references` принимает до 25 значений `q`, а `to` растягивает перебор до второй версии. Сам диапазон
не ограничен; ограничено то, сколько его версий не покрыто предсобранным индексом ссылок, — не
больше 25, потому что каждая такая версия стоит скана джара в 0.4 — 0.8 с и 34-61 МБ. Индекс собран
по релизам, поэтому `releasesOnly=true` берёт 1.14 — 26.2 одним вызовом: 47 релизов за 48 мс,
ответят 43, потому что официальные маппинги Mojang начинаются с 1.14.4. Строка запроса длиннее
4096 байт отбрасывается HTTP-парсером — отсюда предел в 25 целей; формы `POST` и `QUERY` несут до
2000 целей в теле и не кэшируются. Ответ — `{namespace, results[]}`, по записи на пару
(версия, цель) в форме `{version, query, references[]}`. В памяти держится `cache.reference-indexes`
индексов версий, по умолчанию восемь, первым вытесняется тот, к которому дольше всего не обращались.

Индекс записывает владельца из инструкции вызова, а не класс, который объявляет член, поэтому
`Level:getRespawnData` не отвечает ничем, а `ServerLevel:getRespawnData` отвечает 12 местами. Обхода
иерархии нет ни у одного параметра: пустой ответ читается как «ни один вызывающий не называет этого
владельца», дальше спросите подтипы у `/hierarchy` и повторите запрос по каждому.

У каждого места есть `count` — сколько инструкций в нём попадают в цель, и именно их
`@At(ordinal = N)` нумерует `0 .. count-1`. Вызов внутри лямбды отдаёт в `member` метод, в котором
лямбда написана, а в `synthetic` — тело, в которое её скомпилировал javac (`lambda$tick$3`). Вызовы
внутри самого вызывающего класса индексируются, ссылки на методы прослеживаются через
`invokedynamic`. `depth` больше 1 добавляет `paths` — цепочки до цели, внешним кадром вперёд, не
больше 200 штук.

`diff/references` группирует эти места по методу, в котором они лежат, и считает разницу между двумя
версиями. `moved` сопоставляет удалённое место с добавленным, когда оба достают один и тот же набор
членов: сначала по имени метода, затем по классу, затем единственную оставшуюся пару. `404`, если
named-jar нет ни у одной запрошенной версии.

`exists` читает объявления версии по классу из `mappinglens-decl.db`, а для версии, которой в этом
файле нет, сканирует named-jar через ASM. Имена в обоих случаях берутся из named-jar, поэтому
дескрипторы совпадают без ремаппинга. До 2000 ключей за запрос, `404`, когда ответить нечем, ответ
не кэшируется.

У промахнувшегося ключа `closest` содержит ближайшее объявление в той же форме ключа, а `reason` —
чем оно отличается:

- `inherited`: точно такую сигнатуру объявляет супертип, вызов в рантайме резолвится. Таргет `@At`
  валиден, а `@Shadow` должен называть супертип.
- `descriptor`: владелец объявляет это имя с другим дескриптором **того же вида**, то есть сигнатура
  поменялась.
- `kind`: владелец объявляет это имя полем там, где спросили метод, или наоборот. Подставить
  `closest` вместо ключа нельзя.

Кандидат того же вида выигрывает у кандидата другого вида, и поэтому `descriptor` означает именно
то, что написано. Оба поля пусты, когда версия не знает такого имени под этим владельцем, и когда
`exists` = true.

Ключ без дескриптора — это резолв, а не проверка существования: вместо голого `false` возвращается
`candidates`, все объявления под этим именем в форме ключа, без ранжирования и без фаззи-поиска.
`closest` и `reason` остаются пустыми.

### Ресурсы

| Эндпоинт                         | Описание                                                                                   |
|----------------------------------|--------------------------------------------------------------------------------------------|
| `GET /api/v1/resources/versions` | Версии в индексе ресурсов, от новых к старым, с ветками каждой                             |
| `GET /api/v1/resources/tree`     | Один уровень каталога одной версии                                                         |
| `GET /api/v1/resources/file`     | Байты одного файла, с `Content-Type` по расширению и с git-блобом в ETag                   |
| `GET /api/v1/resources/diff`     | Все пути, различающиеся между двумя версиями, с id блоба с каждой стороны                  |
| `GET /api/v1/resources/history`  | Диапазоны версий, в которых один путь держал каждое своё содержимое                        |
| `GET /api/v1/resources/search`   | Полнотекстовый поиск по содержимому (`type=content`) или по переводам (`type=translation`) |

Параметры: `branch` (`assets`, `diff`, `registries` или `atlas`, по умолчанию `assets`), `version`,
`from`/`to`, `path`, а у поиска — `q`/`type`/`version`/`limit`. Версию можно назвать её mcmeta-id
(`26.3-snapshot-9`), отображаемым именем mcmeta (`26.3 Snapshot 9`) или id версии MappingLens.

Сервер не строит текстовый дифф. `/file` отдаёт сырые байты, поэтому клиент кладёт PNG в элемент
`img`, а OGG — в `audio`, а текстовый файл читает в обеих версиях и скармливает своему diff-виду.

Совпадение по содержимому указывает на блоб, поэтому одно и то же содержимое, разделяемое
несколькими путями, приходит по записи на путь. Совпадение по переводу указывает ключ перевода,
языковой файл и диапазон версий, а не один файл. Каждый терм `q` ищется как фраза, поэтому
`minecraft:copper_golem` — это запрос, а не фильтр по колонке FTS5.

Если клон не настроен или его индекс не собран, все эндпоинты отвечают `404 resources_disabled`.

## Общие правила контракта

- **Неймспейсы:** `yarn`, `mojmap`, `intermediary`, `obfuscated` (алиас `obf`). Где какие
  допускаются — см. таблицы выше.
- **Версия по умолчанию** (search, translate) — последний `release` по semver-порядку.
- **Ошибки** — единый `ApiError { error, message, status }`, где `status` дублирует HTTP-код:
  `400 invalid_query`, `404 not_found`, `422 namespace_unavailable`.
- **Форматы ответов:** JSON по умолчанию; `bytecode/source/tokens?format=text` → `text/plain`;
  патч (`format=patch/git`) → `text/x-diff`.
- **`hasIntermediary`** — версия имеет intermediary-имена, а не отдельный intermediary-файл. Yarn
  tiny v2 устроен как `official->intermediary->named`, поэтому любая yarn-версия отдаёт
  intermediary. Unobfuscated-релиз, который yarn не покрывает, отдаёт intermediary только при
  заданном `sources.unobfuscated-intermediary-mappings`.
- **`hasMojmap`** — у unobfuscated-релизов тоже true: имена Mojang уже лежат в самом jar, поэтому
  `obfuscated` и `mojmap` возвращают там одно и то же имя.
- **Rate limit:** 200 запросов / 60 с на `/api/v1`; мета-эндпоинты не лимитируются.

### Поведенческие замечания (важно для агентов)

- `search.totalResults` — размер **текущей страницы**, а не общее число совпадений.
- `diff*` с несуществующей версией возвращает **200** с пустым результатом, не 404.
- `translate` и `compare` с несуществующей версией возвращают **404**, не 422.
- `compare`: параметр `to` валидируется, но на выборку не влияет.
- `/diff/files`: `context`, `limit` и `function` читаются только при `format=patch/git`.

## Что хранит индекс

SQLite-индекс держит `versions` (метаданные, semver-порядок, counts) и унифицированные
obf-ключённые строки `classes`/`methods`/`fields` (с `presence ∈ {both, yarn_only, mojmap_only}`).
Декомпилированный исходник, байткод и git-блобы он не хранит — они читаются по требованию из
read-only стора.

Рядом лежат четыре файла:

- **`mappinglens-search.db`** — по одной contentless FTS5-таблице на версию, с именем
  `search_v<row id версии>`. FTS5 отвечает на префиксный терм так: сливает doclist'ы всех термов с
  этим префиксом по всей таблице и только потом сужает по rowid, поэтому одна таблица на все версии
  читала 5.5 млн постингов на `get*`, чтобы отранжировать 13697 строк нужной версии. Таблица на
  версию отвечает за 24 мс вместо 959 и стоит на 2% больше байт. Таблицы contentless, потому что
  сервер не читает из них имён: идентификатор строки лежит в rowid, вид элемента — в двух младших
  битах. На 52.3 млн строк файл занимает 5.3 ГБ против 14.9 ГБ у одной таблицы, которую он заменил.
  Файл отдельный, потому что 526 виртуальных таблиц добавляют около 2600 строк в `sqlite_master`, а
  сервер открывает соединение на каждый запрос.
- **`mappinglens-refs.db`** — по строке на класс каждой пары (версия, namespace), а в строке — кто
  ссылается на каждый его член, сжатый deflate. Без него сервер сканирует весь named-jar версии при
  первом вопросе о ней: 0.4 — 0.8 с и 34-61 МБ. Чтение строки стоит 0.7 мс на новом соединении и
  0.1 мс на прогретом. Строка на класс, а не на член, потому что класс — единица, которую
  спрашивают, и потому что такие блобы жмутся в 6.8 раза против 2.7. `index` собирает файл по
  релизам (90 пар, 1.0 ГБ, 57 с), `-refs=all` — по всем версиям (10.3 ГБ, 11 минут), `-refs=none`
  пропускает шаг. Файл необязателен и может быть частичным: непокрытая версия отвечается сканом.
- **`mappinglens-decl.db`** — по строке на класс каждой пары (версия, namespace), а в строке —
  флаги доступа, прямые супертипы, прямые подтипы и каждый член в форме `name:descriptor`, сжатые
  deflate. Из него читают `exists` и `hierarchy`. Без него каждый из них сканирует весь named-jar
  версии при первом вопросе о ней (227 — 318 мс) и держит граф в памяти. Чтение строки стоит 10 мкс
  и не держит ничего. Основной индекс его не заменяет: `exists` ключуется на
  `owner:name:descriptor` в целевом namespace, а в таблицах членов нет yarn- и mojmap-дескриптора,
  и ни рёбер подтипов, ни флагов доступа нет нигде, кроме джарника. `index` собирает файл по всем
  версиям (4.2 МБ на пару, 4.3 ГБ и 7 минут на все 526 в обоих namespace), `-decl=releases` сужает
  охват, `-decl=none` пропускает шаг. Необязателен и может быть частичным, как reference-индекс.
- **`mappinglens-resources.db`**, который собирает `index-resources`, тоже не хранит содержимое
  файлов. Его основная таблица — `runs`: одна строка покрывает `(путь, блоб, from_ord, to_ord)`, и
  эти же 199k строк отвечают на дерево версии, дифф двух версий, историю пути и версии совпадения.
  Рядом лежат contentless FTS5-индекс по 85k текстовых блобов и 1.87M строк на диапазоны ключей
  перевода. Весь файл — 313 MiB на 450 версий четырёх веток, одна сборка занимает меньше двух минут.
  Байты берутся из клона через `git cat-file`.

### Члены unobfuscated-релиза

Intermediary называет переопределяющий метод только в том классе, который объявляет его первым,
дальше имя наследуется. У обфусцированного релиза это незаметно, потому что его mojmap-tiny
перечисляет каждый объявленный член. У unobfuscated-релиза mojmap-tiny нет, поэтому разбор одних
маппингов не даёт ему оверрайдов вообще.

Для таких релизов индексатор читает джарник самой версии и добавляет члены, которых нет в маппингах.
Члены, известные маппингам, сохраняют свои yarn- и intermediary-имена; известные только джарнику
попадают как mojmap-only. Классы в обоих случаях берутся из маппингов.

Масштаб пробела до исправления: у `1.21.11` было 89 606 методов против 56 986 у
`1.21.11_unobfuscated`, а `/diff` между ними показывал 32 355 удалённых методов при полном
отсутствии изменений. Поля расходились в пределах 1%, потому что поле не переопределяется. Индекс,
собранный до исправления, несёт пробел, пока затронутые версии не переиндексированы.
